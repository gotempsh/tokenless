## 1. Start the control plane

```sh
tokenless serve --data-dir ./tokenless-data
```

On first start it creates the admin account and prints its username and
password once:

```text
  Created the first admin. Save these now: the password is shown only once.

    Username  admin
    Password  k7mq2-...
```

Put them in a password manager. Only a hash of the password is stored, so
it can't be shown again; if you lose it, run
`tokenless admin reset-password --data-dir ./tokenless-data` on the same
machine. Sign in at [http://127.0.0.1:8080/](http://127.0.0.1:8080/). Under **Account** you can
change the password and turn on an authenticator app, which is
recommended for admins.

`serve` also runs the proxy agents on this machine go through, on
`127.0.0.1:3128`. It shows under **Proxies** as *built-in (this server)*.
Version 0.3 and earlier don't: there, open **Proxies → Add a proxy** and
run the two commands it shows in another terminal, or update with
`tokenless update`.

Every step below can also be done from the terminal; see
[Set up from the terminal](./terminal.mdx).

## 2. Add a service

1. Open **Vaults** and create a vault, for example `work`.
2. Click **Add service**, pick **GitHub** and click it.
3. Choose the vault, what agents may do (**Full access** or
   **Read only**), and an access bundle. Create a new bundle called
   `code-review`.
4. Paste the token and save.

This stores the credential, adds a rule that lets agents use it, and puts
that rule in the `code-review` bundle. The token is write-only from now
on: nobody can read it back.

Use **Test** on the service's page to check the token works.

## 3. Sign in from the terminal

```sh
tokenless login
```

`run` then mints sessions with your account. This sign-in can only start
sessions, so an agent that finds it can't change anything; for terminal
commands that do, sign in with `tokenless login --manage`, which lasts an
hour ([Access and least privilege](./access.mdx)). For an agent on another
machine, or a CI job, create a session instead: on the bundle's page,
**Run an agent → New session**, then
`export TOKENLESS_SESSION_TOKEN=v4.public...` there and
`tokenless run -- <command>`. The token reaches the bundle's services
until it expires or you revoke it, and nothing else.

## 4. Run something behind it

```sh
tokenless run --vault work --bundle code-review -- curl -s https://api.github.com/user
```

The request reaches GitHub with your token, and `curl` never had it.
Try a host outside the bundle and the proxy passes it through untouched
(or refuses it, depending on [Settings](./settings.mdx)).

Now start a real agent the same way:

```sh
tokenless run --vault work --bundle code-review -- claude
```

The session appears under **Sessions**, and every request it makes under
**Audit log**. When the agent exits, its session ends.

## Give your agent the skill

```sh
npx skills add gotempsh/tokenless
```

It teaches the agent to check what it can reach and to read the proxy's
refusals instead of looking for a key. An agent not yet behind tokenless
offers it when a key comes up (you paste one, ask it to write one into
`.env`, or a tool fails for want of one) and walks you through storing
the key in a vault, typed by you, never seen by the agent. See
[Run an agent](./agents.mdx#the-agent-skill) for other ways to install it.
