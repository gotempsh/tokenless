Let an agent use your GitHub token without ever holding it

tokenless is a credential broker for AI agents. Their HTTPS traffic goes through a proxy you run, and for hosts that have a rule, the proxy adds the real credential on the way out. The agent gets a proxy address and a placeholder. The proxy is authenticated: a connection without a valid session token gets 407 and nothing else.

Get started See a session in the terminal

The path a request takes

A request passes four stops between the agent and the API. The agent and its session port never see the credential. The proxy node holds it in memory, sealed to that node's own key, and adds it only for hosts covered by a rule in the agent's session.

  1. The agent

    started by tokenless run

    Its environment has HTTPS_PROXY pointing at a loopback port, trust files for the broker's CA and any placeholders the bundle exports. It has no session token and no API key.

  2. The session port

    127.0.0.1:<free port>

    Adds the session token to each connection and relays it to the proxy. It renews the session before it expires (15 minutes by default) and ends it when the agent exits.

  3. The proxy node

    127.0.0.1:3128

    Refuses any connection that has no session token. Checks the token's signature, expiry and revocation, then the rule's hosts, methods and paths. It swaps in the credential, writes the audit record and forwards. Hosts without a rule are tunnelled untouched, or refused if you set the policy to deny.

  4. The API

    api.github.com

    Gets an ordinary request with a valid token.

Behind it, the control plane

tokenless serve runs the web console and management API on 127.0.0.1:8080 and the node API on 8443. It sends each proxy node an Ed25519-signed policy snapshot with a 60-second lease. When the lease runs out, because the control plane is down or the node was revoked, the proxy refuses all traffic with a 503 until a fresh snapshot arrives.

A session, from the terminal

In the console you create a vault, paste a GitHub token, add a rule for it and put the rule in an access bundle called code-review. Here the rule allows GET and POST on /repos/*, and the token has the placeholder __GITHUB_TOKEN__. Then you start the agent with the bundle.

The API key has the session_issuer role: it can mint sessions in one vault and do nothing else. The agent doesn't inherit it.

session info lists what the session reaches. It never prints a secret.

The first curl sends no Authorization header at all. The proxy adds it.

The DELETE is outside the rule, so the proxy answers 403 with the reason and records a proxy.deny event.

run exits with the agent's exit code, after ending every session it minted.

exec fills variables by reference. The script gets the placeholder, and the proxy swaps it for the secret only on GitHub's hosts.

An --env-file of these references contains no secrets, so you can commit it.

MCP clients connect by URL

Claude Code, Cursor and other clients that take a server URL use the proxy node's MCP gateway on 127.0.0.1:3129. tokenless mcp mints one session for the bundle and prints the client configuration, with the session token as the bearer token.

Run the printed line to add the server. The client stores the session token, and the GitHub credential stays with the proxy.

The session ID and expiry go to stderr, with the command that revokes it.

The token lasts as long as Settings → Session lifetime allows: an hour unless an admin raises it, up to 7 days. Pass --ttl for less.

Only the streamable HTTP transport is supported.

A rule for an MCP server can list the tools a tools/call may name. The proxy reads only the method and the tool name, never the arguments.

Any other tool gets this JSON-RPC error from the proxy instead of reaching the server, and the refusal is audited as proxy.deny.

Security model

If an agent is compromised, the most it can leak is a session token. That token is bound to specific rules, lasts an hour at most unless an admin raises the cap, and can be revoked within seconds.

The proxy is authenticated

Every connection to the proxy carries a session token, a PASETO v4.public token that the control plane signs with Ed25519. The proxy checks the signature against keys from its signed snapshot, without calling the control plane, then the token's expiry and revocation. It does this on the CONNECT and again on every request inside the tunnel.

Without a valid token the proxy answers 407, whatever the host, including hosts with no rule. A process that finds the port can't use it as an open proxy.

MCP clients send the same token to the gateway as Authorization: Bearer and get 401 without it. Proxy nodes authenticate to the control plane with a client certificate issued when they join and renewed automatically.

Secrets are write-only

You paste a credential once and never see it again. No role can read one back, admins included: the API has no endpoint that returns a value, and the metadata type has no field that could carry one. Values are encrypted at rest with AES-256-GCM under a master key file. Rotating a credential replaces the value and returns metadata only.

The end-to-end test checks this: it searches every read endpoint and the raw database files for the plaintext.

Every request is audited

The proxy records every request it adds a credential to or refuses, and every tunnel it opens to other hosts. The control plane writes an audit row in the same transaction as each change it makes. Some of the events:

proxy.inject, proxy.response
a credential was added, and what came back
proxy.deny
a rule or a tool allowlist refused the request
proxy.gateway_denied
an MCP client asked for a host outside its session
session.mint, session.revoke
a session started or ended

Audit records wait in a queue of up to 4,096 events. When it is full, the proxy answers 503 instead of injecting, so no credential goes out without a record.

Revocation cuts the agent off

Revoke the session on the Sessions page or from the CLI, disable the rule, or delete the bundle, which ends every live session minted from it. The change reaches the proxy in its next signed snapshot, and the agent's next request gets 407 (an MCP client gets 401).

What the proxy answers when it refuses
StatusWhen
407The session is missing, malformed, expired or revoked.
403No rule allows the method and path, the request is plain HTTP, or the host resolves to a private, loopback or metadata address. Credentials are never sent over plain HTTP.
429The session has used up its request limit.
503The policy lease has expired, or the audit queue is full.

Each refusal carries a plain-text reason. tokenless skill --install adds a skill to Claude Code that tells the agent how to read these answers and not to work around them.

About 160 services are built in

One binary, on your machines

tokenless is a single binary with the console built in, for Linux and macOS. serve runs the control plane with SQLite and the web console, and node run runs a proxy next to your agents. Everything sensitive in broker.db is encrypted with master.key; back them up separately. The documentation covers production deployments, the container image and building from source.

The script checks the download against the release's checksums, and its signature when cosign is installed. On first start, serve creates the admin and prints its password once. Sign in at http://127.0.0.1:8080/ or with tokenless login. More people join by invitation as viewer, editor or admin.

Create the join token on the console's Proxies page. The node listens on 127.0.0.1:3128 for agents and 127.0.0.1:3129 for MCP clients.

It tells an agent behind the proxy how to see what it can reach, hand a tool a placeholder instead of a key, and read a 403 without trying to get around it. Works with Claude Code, Cursor, Codex and the other agents the skills CLI supports; tokenless skill --install does the same without Node.

Images for amd64 and arm64, signed with cosign, built from the same static binaries as the release archives.
